# 🏗️ Stock Monitor v7.0 - Architecture Refactoring Release

**发布时间**: 2026年1月21日
**Release Date**: January 21, 2026
**更新类型**: ⚙️ **架构现代化重构** | Modernized Architecture Refactoring

## 🎯 版本概述 | Version Overview

v7.0 是一次**重要的架构升级**，将整个项目从混合的单体文件结构重构为**清晰的模块化 `internal/` 包架构**。这是一次不改变功能的「内部重组织」，旨在为未来的扩展、维护和测试奠定坚实的基础。

**Major Points:**
- ✨ **完整的 `internal/` 包重构** - 从 9,773 行根目录代码 → 12,090 行模块化内部包
- 📦 **15 个独立核心包** - API、数据层、UI、市场处理、告警系统等明确分层
- ✅ **100% 功能兼容** - 所有 v6.0 功能保留，用户无需修改任何配置
- 🧪 **40+ 单元测试** - 覆盖告警、分时、市场、API 等所有核心模块
- 🚀 **性能无损** - 架构优化不影响性能（~21,863 总行数）

**Architecture Evolution:**
```
v5.0: 完整模块化 (16 modules, ~14K lines)
v6.0: 加入告警系统 (+2,733 lines, 22 modules)
v7.0: 重构为 internal/ 包 (15 internal packages, 保留根目录文件兼容)
     ↓
清晰的分层架构，为 v8.0+ 做准备
```

### 2. 清晰的分层架构 | Layered Architecture

```
┌────────────────────────────────────────┐
│   UI Layer (表现层)                     │
│   - internal/ui/: 表格、颜色、输入     │
│   - Alert UI, Watchlist UI             │
│   - main.go: 状态机与事件循环          │
├────────────────────────────────────────┤
│   Business Logic Layer (业务逻辑层)    │
│   - internal/alert/: 频率控制          │
│   - internal/intraday/: 数据采集管理   │
│   - internal/market/: 时区、交易时间   │
│   - internal/sort/: 排序引擎           │
├────────────────────────────────────────┤
│   Data Layer (数据层)                  │
│   - internal/data/: 持久化、缓存       │
│   - internal/types/: 数据结构          │
│   - Atomic writes, 30s TTL cache       │
├────────────────────────────────────────┤
│   External Integration (外部集成)       │
│   - internal/api/: 多源 API 集成       │
│   - internal/intraday/: 后台工作       │
│   - Fallback chains: Tencent→Sina→...  │
├────────────────────────────────────────┤
│   Cross-Cutting (横切关注)             │
```

**设计优势:**
- ✅ 清晰的依赖方向（顶层依赖底层，不反向）
- ✅ 每个包可独立测试和重用
- ✅ 新功能易于添加（在对应层实现）
- ✅ 团队成员快速定位代码

### 3. 包设计原则 | Package Design Principles

#### API 包 (`internal/api/`)

**职责**: 多源 API 集成与数据转换

```go
// 统一接口
internal/api/stock.go:
  ├── GetStockPrice(symbol) *StockData      // 主接口
  ├── SearchStock(query) []SearchResult     // 搜索
  └── fallback chain: 腾讯→新浪→东方财富

// 市场特定实现
internal/api/china/tencent.go:
  └── FetchTencentPrice(symbol) *StockData

internal/api/china/sina.go:
  └── FetchSinaPrice(symbol) *StockData

internal/api/us/yahoo.go:
  └── FetchYahooPrice(symbol) *StockData

// 通用工具
internal/api/common/converters.go:
  ├── ConvertStockCode(input) apiCode      // 601138 → 601138.SS
  └── HandleGBKEncoding(response) string   // GBK → UTF-8
```

#### Data 包 (`internal/data/`)

**职责**: 数据持久化、缓存、仓库模式

```go
internal/data/cache.go:
  ├── Get(key) value              // RWMutex 保护的读
  ├── Set(key, value)             // 互斥写
  └── 30-second TTL

internal/data/persistence.go:
  ├── SavePortfolio(portfolio)    // JSON 原子写
  ├── LoadWatchlist() watchlist   // 版本兼容加载
  └── Migration logic

internal/data/portfolio_repository.go:
  └── Repository pattern          // 数据访问抽象
```

#### Intraday 包 (`internal/intraday/`)

**职责**: 后台数据采集，worker 池管理

```go
internal/intraday/manager.go:
  ├── StartCollection()           // 启动采集
  ├── workerPool chan struct{}    // 信号量 (max 10)
  └── activeStocks sync.Map       // 活跃股票跟踪

internal/intraday/worker.go:
  ├── CollectIntraday(code)       // 单个 worker
  └── 智能重试与失败处理

internal/intraday/storage.go:
  ├── SaveData(code, date, data)  // 原子文件写
  └── 文件锁 (sync.Map pattern)

internal/intraday/trading.go:
  └── IsMarketTrading(code, time) // 市场时间检测
```

#### Alert 包 (`internal/alert/`)

**职责**: 告警频率控制与检查

```go
internal/alert/frequency.go:
  └── CanTriggerInCurrentPeriod(alert) bool
      ├── Once: first trigger only
      ├── Daily: same-day blocking
      ├── Weekly: week boundary
      ├── Monthly: month boundary
      └── Custom: interval calculation

internal/ui/alert/checker.go:
  └── CheckAlertConditions()  // 价格/涨幅/成交量检查
```

#### Market 包 (`internal/market/`)

**职责**: 市场特定逻辑

```go
internal/market/timezone.go:
  ├── GetMarketTimezone(market)   // A股/美股/港股 时区
  └── ConvertToMarketTime(utc)    // 市场本地时间

internal/market/holiday.go:
  ├── IsTrading(market, date)     // 是否交易日
  └── GetTradingHours(market)     // 交易时间段
```

### 4. 依赖管理 | Dependency Management

**明确的依赖方向** (避免循环依赖):

```
types/ ← (所有包依赖的基础)
errors/ ← (所有包可依赖错误定义)
↑
├─ data/ (type + errors)
├─ api/ (type + errors + i18n)
├─ log/ (type + errors)
├─ i18n/ (type)
├─ intraday/ (type + data + market + api)
├─ alert/ (type + market)
├─ market/ (type)
└─ ui/ (type + data + format)
```

**禁止的依赖** ❌:
- UI 包不能依赖 main.go
- 业务逻辑包不能互相依赖
- API 包不能依赖 intraday
- Data 包不能依赖 UI

## 🔧 技术实现 | Technical Implementation

### 包初始化顺序 | Package Initialization

```
main.go
  ├─ init() // 加载配置
  ├─ app/init.go
  │  ├─ types 包初始化
  │  ├─ i18n 包初始化
  │  ├─ log 包初始化
  │  ├─ data 包初始化 (缓存、持久化)
  │  └─ intraday 包初始化 (worker 池)
  └─ Update()/View() // 事件循环
     ├─ 调用 ui/ 包渲染
     ├─ 调用 api/ 包获取数据
     ├─ 调用 market/ 包检查时间
     └─ 调用 alert/ 包检查告警
```

### 并发模型保持 | Concurrency Model Preserved

**所有并发原语保留:**

```go
// Cache access - RWMutex
internal/data/cache.go:
  mu sync.RWMutex  // 保护高读并发

// Worker pool - Semaphore
internal/intraday/manager.go:
  workerPool chan struct{}  // max 10 并发

// File locks - sync.Map
internal/intraday/storage.go:
  fileLocks sync.Map  // 每文件一个 Mutex

// Message passing - Bubble Tea
main.go:
  Update(): 从 goroutine 发送 tea.Msg
```

## 📚 开发指南 | Developer Guide

### 添加新功能 | Adding New Features

**在 `internal/` 包中开发:**

```go
// 1. 新特性属于哪一层?
// 是 UI → internal/ui/
// 是业务逻辑 → internal/{alert,intraday,market}/
// 是数据 → internal/data/
// 是 API → internal/api/

// 2. 创建新包/文件
internal/feature/main.go
internal/feature/handler.go
internal/feature/types.go
internal/feature/feature_test.go

// 3. 定义清晰的接口
type FeatureService interface {
    Method1() error
    Method2() string
}

// 4. 添加单元测试
internal/feature/feature_test.go:
    func TestMethod1(t *testing.T) { ... }
    func TestMethod2(t *testing.T) { ... }

// 5. 从 main.go 或其他包调用
import "stock-monitor/internal/feature"
feature.Method1()
```

### 修复 Bug | Bug Fixing

1. **定位问题** - 快速查看 CLAUDE.md 中的"Where to Find"表
2. **找到相关包** - 问题在 internal/ 的哪个包?
3. **编写测试** - 再现 bug 的单元测试
4. **修复实现** - 修改最小代码
5. **验证修复** - 确保测试通过 + 无新竞态

### 模块间通信 | Inter-module Communication

**推荐模式:**

```go
// ✅ Good: 通过接口解耦
type DataService interface {
    Save(data interface{}) error
}

type APIClient struct {
    data DataService
}

// ✅ Good: 依赖注入
func NewAPIClient(data DataService) *APIClient {
    return &APIClient{data: data}
}

// ❌ Bad: 直接导入全局变量
var globalCache = &Cache{}  // 难以测试

// ❌ Bad: 循环依赖
// A → B → A
```

## 💡 架构决策与权衡 | Architecture Decisions & Tradeoffs

### 为什么保留根目录文件?

**Pro (保留):**
- ✅ 零迁移风险
- ✅ 向后兼容
- ✅ 可以逐步迁移
- ✅ 现有依赖不破坏

**Con (保留):**
- ❌ 代码重复
- ❌ 可能混淆新开发者
- ❌ 需要同步两份代码

**决策**: 在 v7.0 保留，v8.0 删除。这给开发者充足的过渡期。

### 为什么选择 internal/ 目录?

**Go 标准做法**:
- ✅ Go 官方推荐的包隐私机制
- ✅ 可以导出包但隐藏实现细节
- ✅ IDE 和工具完全支持
- ✅ 社区普遍采用 (Kubernetes, Docker 等)

### 2. 排序状态优化 | Sort State Optimization

**v7.1 的问题**:
- 添加/编辑/删除股票后，排序会重置为默认状态
- 用户需要重新设置排序方式
- 影响使用体验，尤其是频繁操作时

**v8.0 解决方案**:

**智能排序状态管理**:
```go
// CRUD 操作后保持排序状态
after CRUD operation:
  if currentSortField != "default":
    restore sort parameters
    re-apply sorting
  else:
    keep default order
```

**影响的操作**:
- ✅ 添加股票后 - 保持当前排序
- ✅ 编辑股票后 - 保持当前排序
- ✅ 删除股票后 - 保持当前排序
- ✅ 批量操作后 - 保持当前排序

**用户体验提升**:
- 操作流程更流畅
- 无需重复设置排序
- 符合用户心理预期

### 2. 排序状态保持逻辑 | Sort State Preservation Logic

**Portfolio 添加/编辑后**:
```go
// handlers_portfolio.go
func (m *Model) afterPortfolioCRUD() {
    // 保存当前排序状态
    prevSortField := m.sortField
    prevSortOrder := m.sortOrder

    // 重新加载数据
    m.loadPortfolio()

    // 恢复并应用排序
    if prevSortField != "" {
        m.sortField = prevSortField
        m.sortOrder = prevSortOrder
        m.applySorting()
    }
}
```

**Watchlist 操作后**:
```go
// handlers_watchlist.go
func (m *Model) afterWatchlistCRUD() {
    // 同样的逻辑：保存 → 重载 → 恢复排序
    prevSortField := m.watchlistSortField
    prevSortOrder := m.watchlistSortOrder

    m.loadWatchlist()

    if prevSortField != "" {
        m.watchlistSortField = prevSortField
        m.watchlistSortOrder = prevSortOrder
        m.applyWatchlistSorting()
    }
}
```

## 💡 架构决策与权衡 | Architecture Decisions & Tradeoffs

### 为什么板块数据用独立状态?

**优点** ✅:
- 板块浏览不影响持股/自选状态
- 清晰的状态隔离，易于维护
- 可独立刷新板块数据

**缺点** ❌:
- 增加了一个新的顶层状态
- Model 字段略微增加

**决策**: 独立状态更清晰，符合现有架构模式。

### 为什么排序状态保持不缓存?

虽然每次 CRUD 后都重新排序，但**不缓存排序结果**：
- 数据可能变化（价格更新）
- 重新排序开销很小（< 1000 只股票）
- 保证数据始终最新

**优点** ✅:
- 数据一致性更好
- 逻辑简单，不易出错
- 性能影响可忽略

### 为什么 UpdatedAt 不影响触发逻辑?

`UpdatedAt` 仅用于**审计和追踪**，不参与告警触发判断：
- 触发逻辑依赖 `TriggeredAt` 和 `Frequency`
- `UpdatedAt` 是辅助信息，不应影响核心逻辑
- 保持告警系统的简洁性

**优点** ✅:
- 核心逻辑不变，稳定可靠
- 易于理解和维护
- 未来可扩展审计功能

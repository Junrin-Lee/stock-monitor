## 数据问题

### 股票数据显示 "-"

**常见原因**：

1. **网络连接问题**
   ```
   检查: ping baidu.com
   如果无网络，等待恢复
   ```

2. **股票代码错误**
   ```
   错误格式: 601138 (缺少市场标识)
   正确格式: SH601138 或 sh601138

   检查代码格式: [API 集成](../technical/api-integration.md)
   ```

3. **API 临时故障**
   ```
   解决方案：
   1. 等待 5-10 秒（自动重试）
   2. 手动按 Ctrl+C 重启程序
   3. 检查网络环境
   ```

4. **非交易时间**
   ```
   A 股: 09:30-15:00
   港股: 09:30-16:00
   美股: 21:30-04:00 (北京时间)

   非交易时间显示昨日收盘价或 "-"
   ```

**调试步骤**：

1. 启用调试模式：
   ```yaml
   system:
     debug_mode: true
   ```

2. 重启程序，进入监控页面

3. 按 `D` 键查看日志

4. 查找 API 调用日志：
   ```
   [API] Calling Tencent API for SH601138
   [API] Error: Connection timeout
   [API] Trying Sina API
   ```

### 某些股票始终无法获取数据

**可能是冷门股票**：
- 该股票可能在所有 API 中都无可用数据
- 尝试其他相似股票测试
- 检查股票代码是否真实存在

## 显示问题

### 颜色显示异常

**症状**：显示为白色或全是颜色代码

**原因**：终端不支持 ANSI 颜色

**解决方案**：

1. 使用支持颜色的终端：
   - macOS：Terminal / iTerm2 / Warp
   - Linux：GNOME Terminal / Konsole / xterm
   - Windows：Windows Terminal / Git Bash

2. 关闭颜色（临时）：
   ```yaml
   display:
     color_scheme: simple  # 简洁模式
   ```

### 中文显示乱码

**症状**：中文字符显示为 ??? 或其他符号

**原因**：
- 终端编码不是 UTF-8
- 终端字体不支持中文

**解决方案**：

1. **检查终端编码**（macOS/Linux）：
   ```bash
   echo $LANG
   # 应该看到 en_US.UTF-8 或 zh_CN.UTF-8
   ```

2. **设置 UTF-8 编码**：
   ```bash
   export LANG=en_US.UTF-8
   export LC_ALL=en_US.UTF-8
   ./cmd/stock-monitor
   ```

3. **更改终端字体**：
   - 终端设置 → 字体 → 选择支持中文的字体
   - 推荐：Courier New, Monospace, 等宽字体

4. **作为最后手段 - 切换到英文**：
   ```yaml
   system:
     language: en
   ```

### 表格对齐错乱

**原因**：可能是中文字符宽度计算错误

**解决方案**：
- 通常会自动调整，等待几秒
- 如果问题持续，调整终端窗口大小
- 增加 `max_lines` 配置值

## 性能问题

### 程序响应慢

**症状**：按键响应延迟、数据更新缓慢

**原因**：
1. 网络不稳定
2. 刷新间隔设置过短
3. 同时加载太多股票

**解决方案**：

1. **增加刷新间隔**：
   ```yaml
   update:
     refresh_interval: 10  # 改为 10 秒
   ```

2. **检查网络连接**：
   ```bash
   ping -c 5 8.8.8.8
   ```

3. **减少同时监控的股票**：
   - 删除不需要的自选股票
   - 使用标签分组，只显示需要的股票

### 内存占用过高

**症状**：程序逐渐变慢，最终卡住

**原因**：
- 分时数据文件过大
- 同时加载太多数据

**解决方案**：

1. **清理分时数据**：
   ```bash
   # 删除旧数据（保留最近 30 天）
   find data/intraday -name "*.json" -mtime +30 -delete
   ```

2. **禁用分时采集**（如果不需要）：
   ```yaml
   intraday_collection:
     enable_auto_stop: true
   ```

3. **重启程序**

## 告警问题

### 告警未触发

**检查清单**：

```
□ 1. 告警已启用？
     - 在告警列表中检查，Space 切换启用/禁用

□ 2. 条件是否满足？
     - 查看当前股价，确认是否达到条件

□ 3. 频率是否允许触发？
     - "一次性"：触发一次后自动禁用
     - "每日"：同一天只触发一次
     - "每周"：同一周只触发一次

□ 4. 是否超过最大错误次数？
     - 如果 API 调用失败超限，告警会自动停用

□ 5. 操作系统是否允许通知？
     - macOS: 系统偏好 → 通知 → 启用 Stock Monitor
     - Linux: 检查 D-Bus 通知服务
     - Windows: 检查 Windows 通知设置
```

**调试步骤**：

1. 为测试股票创建简单告警（如 AAPL 价格 > 1 元）

2. 启用调试模式查看日志

3. 按 D 键查看日志，搜索关键字：
   ```
   [Alert] Checking alert for AAPL
   [Alert] Condition met: price 189.95 > 1.00
   [Alert] Trigger sent
   ```

4. 检查通知是否出现

### 频率理解不清

**参考表**：

| 频率 | 行为 | 示例 |
|------|------|------|
| 一次性 | 条件满足 → 触发一次 → 自动禁用 | 设置后当天触发一次就够了 |
| 每日 | 每天检查一次，同日仅触发一次 | 每天 10:00 检查一次 |
| 每周 | 每周检查一次，周内仅触发一次 | 每周一 10:00 检查一次 |
| 每月 | 每月检查一次，月内仅触发一次 | 每月 1 日 10:00 检查一次 |
| N 天 | 每 N 天检查一次 | 每 3 天检查一次 |

## 采集问题

### 分时图表无数据

**检查步骤**：

1. **分时采集是否启用？**
   ```yaml
   intraday_collection:
     enable_auto_stop: true
   ```

   如果是 `false`，启用它。

2. **是否在交易时间？**
   ```
   A 股:   09:30-15:00
   港股:   09:30-16:00
   美股:   21:30-04:00
   ```

   分时采集只在交易时间工作。

3. **是否有足够的数据点？**
   ```
   需要至少 20 个数据点（可配置）
   启动后需要等待至少 5-10 分钟
   ```

4. **查看采集进度**：
   ```
   进入分时图表 (V 键)
   查看图表底部的统计信息
   例如: "已采集: 45/60 (75%)"
   ```

### 分时数据採集缓慢

**原因**：
- 网络连接不稳定
- API 响应慢
- 设置的完整性阈值过高

**解决方案**：

1. **降低完整性阈值**：
   ```yaml
   intraday_collection:
     completeness_threshold: 80.0  # 改为 80%
   ```

2. **增加错误容限**：
   ```yaml
   intraday_collection:
     max_consecutive_errors: 10  # 增加容错
   ```

3. **检查网络连接**

## 其他问题

### 程序无法启动

**症状**：执行后立即退出或无反应

**检查步骤**：

1. **确认编译成功**：
   ```bash
   ls -la cmd/stock-monitor
   # 文件应该存在且有执行权限
   ```

2. **检查 Go 版本**：
   ```bash
   go version
   # 应该是 1.25.0 或更高
   ```

3. **重新编译**：
   ```bash
   go clean
   go mod download
   go build -o cmd/stock-monitor
   ```

4. **查看错误日志**（macOS）：
   ```bash
   ./cmd/stock-monitor 2>&1 | tee debug.log
   cat debug.log | tail -50  # 查看最后 50 行
   ```

### 配置文件损坏

**症状**：启动时出现 JSON/YAML 解析错误

**恢复步骤**：

1. **查看错误信息**：
   ```
   Error reading config.yml
   Expected ... at line X
   ```

2. **备份损坏的文件**：
   ```bash
   mv cmd/conf/config.yml cmd/conf/config.yml.bak
   ```

3. **重启程序**：
   ```bash
   ./cmd/stock-monitor
   ```

   程序会自动创建新配置文件。

4. **恢复自定义设置**：
   - 参考备份文件和 [配置说明](../guides/configuration.md)
   - 手工编辑 `config.yml` 恢复配置
